# African Valley Foods

Modern full‑stack TypeScript app for African Valley Foods. The project uses a Vite + React client and an Express server. In development, the Express server mounts Vite middleware for HMR and serves the React app; in production, the server serves the prebuilt static client.

## Tech Stack
- **Client**: React 18, Vite, TypeScript, Tailwind CSS, shadcn/ui (Radix UI), Framer Motion
- **Server**: Node.js, Express
- **Validation & Types**: Zod, Drizzle ORM types (schemas)
- **Build**: Vite (client), esbuild (server)
- **Styling**: Tailwind CSS + `@tailwindcss/typography`, `tailwindcss-animate`
- **Tooling**: TypeScript, `tsx` for dev runtime

## Key Features
- **Lead capture** and **newsletter signup** endpoints with validation
- **Contact form** endpoint with validation
- In‑memory storage by default; optional Postgres schema defined via Drizzle
- HMR dev experience with Vite mounted inside Express

## Scripts
Defined in `package.json`:

- `npm run dev`
  - Starts the Express server with `tsx` (TypeScript runtime) and mounts Vite in middleware mode.
  - HMR is enabled, and the full app is served from the Express server.
  - Default port: **5001** (see `server/index.ts`).

- `npm run build`
  - Builds the client with Vite to `dist/public`.
  - Bundles the server (ESM) with esbuild to `dist/index.js`.

- `npm start`
  - Runs the production server: `node dist/index.js`.
  - Serves the static client from `dist/public` and the API from the same origin.

- `npm run check`
  - Type check with `tsc` (no emit).

- `npm run db:push`
  - Uses Drizzle Kit to push the schema in `shared/schema.ts` to a Postgres database (requires `DATABASE_URL`).

## Running Locally
Requirements:
- Node.js 18+
- npm (comes with Node)

Steps:
1. Install dependencies at the repository root:
   ```bash
   npm install
   ```
2. Start the dev server (Express + Vite HMR):
   ```bash
   npm run dev
   ```
3. Open the app in your browser:
   - http://localhost:5001

The Express server logs requests to `/api/*` with duration and an abbreviated JSON response.

## Building and Running Production Locally
1. Build both client and server:
   ```bash
   npm run build
   ```
2. Start the production server:
   ```bash
   npm start
   ```
3. Visit http://localhost:5001

In production, Express serves the static files from `dist/public` (generated by Vite) and falls back to `index.html` for SPA routing.

## API Endpoints
Defined in `server/routes.ts` and validated with Zod + Drizzle schemas (`shared/schema.ts`).

- `POST /api/leads`
  - Body: `{ firstName, lastName, email, phone, source? }`
  - Creates a lead. Rejects if the email already exists. Returns user‑friendly messages.

- `POST /api/newsletter`
  - Body: `{ email }`
  - Subscribes an email as a newsletter lead if not already present.

- `POST /api/contact`
  - Body: `{ firstName, lastName, email, message }`
  - Creates a contact message and returns a friendly confirmation.

- `GET /api/admin/leads`
  - Returns all leads and a count. (Basic admin utility.)

- `GET /api/admin/messages`
  - Returns all contact messages and a count. (Basic admin utility.)

### Storage
- Default storage is in‑memory (`server/storage.ts`). Data resets on restart.
- Drizzle Postgres schemas are provided in `shared/schema.ts` for future persistence. Use `npm run db:push` to create tables (see Environment Variables).

## Environment Variables
- `DATABASE_URL` (optional unless using Drizzle migrations)
  - Required for `npm run db:push` via `drizzle.config.ts`.

Create a `.env` file at the repo root if needed and export `DATABASE_URL` before running migrations. The running app does not require a database by default due to in‑memory storage.

## Deployment
There are two deployment models you can use:

- Server‑rendered (recommended for full functionality)
  - Build and deploy the Node server (e.g., a VM, Docker, Render, Fly.io, Railway, etc.).
  - Run `npm run build` then `npm start`. Ensure Node 18+.
  - This serves both the static client and API from the same origin on the configured port (5001).

- Static client on Netlify (front‑end only)
  - `netlify.toml` is provided to build and publish the static client from `client/` to `dist/public`.
  - Command: `npm install && cd client && npm install && npm run build`
  - Publish dir: `dist/public`
  - Note: API routes (`/api/*`) will not work on Netlify unless you set up separate server hosting and proxy rules.

## Development Notes
- Dev server binds to `0.0.0.0` on port `5001` (see `server/index.ts`).
- Vite HMR is configured to use the same HTTP server and WebSocket at port 5001 (`server/vite.ts`).
- SPA fallback is handled in both dev and prod (`server/vite.ts`).
